# PopupMessenger Relay

PopupMessenger용 선택적 셀프호스팅 릴레이 서버입니다. 외부망 중계, 오프라인 사용자를 위한 보관 후 전달, 연락처를 제공합니다. 프로토콜은 [docs/relay-protocol.md](../docs/relay-protocol.md)에 있습니다.

## 실행 (Docker)

```bash
cd relay
docker compose up -d --build
```

| 포트 | 용도 |
|---|---|
| `45443/tcp` | 클라이언트 프로토콜. TLS 1.3, 평문(정책이 허용할 때), WebSocket을 같은 포트에서 자동으로 구분 |
| `127.0.0.1:8080` | 관리자 웹 UI. 기본으로 서버 자신에만 열림 |

1. 서버에서 `http://127.0.0.1:8080`을 엽니다. 원격이면 `ssh -L 8080:127.0.0.1:8080 서버`로 터널을 연 뒤 내 PC에서 엽니다.
2. **처음 접속한 사람이 관리자 계정을 만듭니다.** 첫 계정이 생기면 이 화면은 다시 나타나지 않습니다. 그 전에는 관리 포트를 외부에 열지 마세요.
3. 정책 화면에서 로그온 방식, 가입, 암호화, 보관 시간 등을 정합니다. 외부인 가입은 기본으로 **닫혀** 있습니다.

데이터는 `relay-data` 볼륨(`/data`)에 저장됩니다: `relay.db`(SQLite), `blobs/`(맡긴 첨부파일), `tls/`(자체 서명 인증서).

## 환경 변수

| 변수 | 기본값 | 설명 |
|---|---|---|
| `DATA_DIR` | `/data` (Docker), `./data` | 데이터 폴더 |
| `RELAY_BIND` | `0.0.0.0:45443` | 클라이언트 프로토콜 주소 |
| `ADMIN_BIND` | `0.0.0.0:8080` | 관리 UI 주소 (Docker는 compose에서 호스트 loopback으로만 공개) |
| `TLS_CERT`, `TLS_KEY` | (없음) | PEM 인증서 체인과 개인 키. 없으면 `DATA_DIR/tls`에 자체 서명 인증서를 만들어 씀 |
| `TLS_NAMES` | `localhost` | 자체 서명 인증서의 이름(쉼표 구분). 서버의 도메인이나 IP를 넣으세요 |

## Cloudflare Tunnel 등 HTTPS 프록시 뒤에서 쓰기

Cloudflare Tunnel은 HTTP/HTTPS(WebSocket 포함)만 통과시키므로, 클라이언트는 `https://` 주소로 WebSocket 연결을 씁니다.

1. 터널의 Public Hostname을 추가합니다. 예: `pms-relay.example.com` → Service `HTTP` `localhost:45443` (Docker가 호스트에 공개한 릴레이 포트). 대시보드에서 저장하면 DNS CNAME(`<터널 ID>.cfargotunnel.com`)이 자동으로 만들어집니다. `nslookup` 결과가 "Non-existent domain"이면 이 레코드가 없는 것입니다.
2. 관리 화면 > 정책 > 외부 공개에서 "WebSocket 연결"과 "프록시가 TLS 처리"를 켜고, 사용자 접속 주소에 `https://pms-relay.example.com`을 적습니다.
3. 사용자는 앱의 릴레이 서버 연결 창에 `https://pms-relay.example.com`을 입력합니다.

첨부파일은 "스트리밍 단위"(기본 256KB) 크기의 WebSocket 메시지로 나뉘어 오가므로, Cloudflare의 HTTP 업로드 100MB 제한과 관계없이 릴레이 정책의 파일 크기 한도까지 보낼 수 있습니다.

자체 서명 인증서를 쓰면 클라이언트는 처음 연결할 때 SHA-256 지문을 보여 주고 고정합니다. 지문은 관리 UI의 개요 화면에 있습니다.

## 사용자 웹 포털

릴레이 주소(예: `https://pms-relay.example.com`)를 브라우저로 열면 계정 소유자가 자기 계정을 관리하는 화면이 나옵니다. 관리 포트와는 별개입니다.

- 사용자 이름과 비밀번호로 로그인 (비밀번호 계정만, 암호화된 연결에서만. 서버 정책이 평문이면 예외)
- 내 계정 정보, 표시 이름 변경, 비밀번호 변경 (다른 웹 세션은 끝남)
- 등록된 기기 목록, 연결 끊기, 등록 해제 (분실 기기: 다시 쓰려면 비밀번호로 로그인해야 함)
- 내 활동 기록: 가입, 기기 등록·이동·해제, 웹 로그인 등. 관리자가 한 작업은 보이지 않음

관리 화면 > 정책 > 외부 공개 > "사용자 웹 포털"로 끌 수 있습니다.

## 관리 UI

계정, 기기, 접속 현황, 보관함, 쪽지 감사, 감사 로그는 서버에서 쪽 단위(50~500개)로 불러오고 검색·정렬·필터도 서버에서 처리하므로, 사용자가 수십만 명이어도 브라우저에 전체 목록을 내려받지 않습니다.


| 화면 | 내용 |
|---|---|
| 개요 | 접속 기기, 계정, 승인 대기, 보관 쪽지·용량, 만료 알림, 서버 ID·TLS 지문, 현재 정책, 일별 처리량 |
| 접속 현황 | 실시간 연결(TLS/평문, IP, 앱 버전, 접속 시간), 연결 끊기 |
| 계정 | 검색·상태 필터, 승인·정지·해제·삭제(일괄), 계정별 기기 수 한도·저장 한도·메모·비밀번호 재설정 |
| 기기 | 기기별 상태, 앱, IP, E2EE 키 지문, 수신 한도, 받을 쪽지, 연결 끊기·정지·등록 해제 |
| 보관함 | 서버에 맡겨진(아직 전달 중인) 쪽지 목록, 만료 시각, 강제 삭제, 만료 처리 즉시 실행. 평문 쪽지는 행을 눌러 본문·첨부파일 열람 (종단간 암호화 쪽지는 메타데이터만) |
| 쪽지 감사 | 정책에서 "감사 보관"을 켜면 종단간 암호화가 아닌 쪽지의 사본을 전달 후에도 보관(기본 꺼짐, 첨부파일 보관은 별도 선택, 보관 기간 설정). 기간·본문·사람·파일 이름 검색, 본문·첨부 열람, CSV 내보내기. LAN 직접 전송은 서버를 거치지 않아 대상이 아님 |
| 감사 로그 | 관리 작업·가입·기기 등록·로그인 잠금 기록, 쪽지 열람·검색·첨부 다운로드 기록, 필터, CSV 내보내기 |
| 정책 | 클라이언트 정책 5종(로그온, 첨부 한도, 경유 강제, 암호화, 보관 시간)과 가입·연락처 범위·저장 한도·잠금·세션 등 |
| 관리자 | 관리자 추가·삭제, 비밀번호 변경 |

## 버전

서버 버전은 `프로토콜.YYMMDD.NN` 형식입니다 (예: `1.261004.01`). 앞자리는 릴레이 프로토콜 버전(`src/lib.rs`의 `PROTOCOL`), 가운데는 빌드한 날짜, 끝은 그날의 몇 번째 빌드인지입니다. 버전은 `VERSION` 파일에 있고, 새 서버를 빌드하기 전에 `python bump-version.py`로 올립니다(같은 날이면 끝자리 +1, 날짜나 프로토콜이 바뀌면 `.01`부터). 관리 UI 상단, 개요 화면, 클라이언트의 릴레이 계정 정보, 시작 로그에 표시됩니다.

## 업데이트

```bash
git pull                       # 또는 새 소스를 복사
docker compose up -d --build   # 이미지 재빌드 후 컨테이너 교체 (데이터는 볼륨에 유지)
docker compose logs | head     # 첫 줄의 버전이 새 VERSION과 같은지 확인
```

관리 UI는 서버 버전을 붙인 주소로 스크립트를 불러오므로, 업데이트 뒤 브라우저 캐시 때문에 예전 화면이 보이지 않습니다.

## 개발

```bash
cd relay
cargo test          # 실제 포트에서 프로토콜·관리 API 종단 테스트
DATA_DIR=target/dev-data ADMIN_BIND=127.0.0.1:18080 cargo run
```

`45443`은 Windows 동적 포트 범위(49152~65535) 밖으로 골랐습니다. 그 범위는 Hyper-V/WinNAT가 대량으로 예약해 바인딩이 거부될 수 있습니다.
